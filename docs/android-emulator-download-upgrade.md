# Android emulator: installed download upgrade and Open/Share

This branch-scoped [workflow](../.github/workflows/android-emulator-poc.yml) checks the installed SQLite upgrade portion of **DL-01** and actual Android delivery and grant confinement in **DL-04**. It does not repeat the earlier [pre-commit publication interruption](android-emulator-download-recovery.md#verified-result).

## What the run checks

- **Real replacement, not an in-memory migration.** Restore the pinned Step 19 sources with [`prepare_perf_baselines.py`](../tools/prepare_perf_baselines.py). Build those sources and the exact candidate commit normally, verify the APK package names, SHA-256 digests and signing certificates, and install the v7 build first. Both APKs are `com.browser` debug builds; v7 and v8 refer to the SQLite schema, not Android's `versionCode`. The v7 app creates the database and completes a synthetic download through Downloads. While that app is stopped, add synthetic `PENDING`, manually `PAUSED`, and interrupted `RUNNING` rows to a copy of its own database, with two genuine partial byte prefixes, saved segment positions and strong validators. Seed test-only legacy values in those three rows. Replace with `adb install -r`, without uninstalling or clearing data. Check that the UID, v7 database bytes and private marker still match before starting the candidate.
- **Recovery in the upgraded app.** Launch the browser, not a migration helper. Require SQLite v8, populated name keys and history indexes, and the original completed row, file identity and bytes. The pending job starts from zero; the interrupted job uses its exact conditional HTTP range. The fixture holds the response briefly to check the saved prefix, segment position and inode independently. The pause stays unchanged through the other checks until the user-facing Resume control is tapped, then continues from its own exact offset. Verify all output lengths and SHA-256 digests and reject any unexpected requests, cookies, authorization, referrers or reuse of the seeded user agent. This verifies **non-use on the wire**, not deletion of those columns in v7 → v8.
- **Real recipient, not a constructed intent or a shell grant.** The [offline fixture app](../tests/fixtures/download_upgrade/AndroidManifest.xml) has a separate UID and signer and requests no permissions. Tap a completed card and use its long-press **Open File**; then use **Share File** and select two rows for multi-Share. Choose that app in Android's real sharesheet for each Share. It checks the actual `ACTION_VIEW` / `ACTION_SEND` / `ACTION_SEND_MULTIPLE` intent and ClipData and independently reads and hashes each stream. Before each delivery it verifies no lingering grants. It also attempts write access, a different completed sibling, the private staging file and its would-be URI, a wrong attempt token, and a URI descendant. Shell ADB drives UI and reads the fixture receipts; it does not grant access to any download URI.
- **Replacement and removal.** In the emulator-only directory, replace a selected file with a distinct file of the same length. A still-granted recipient must be unable to reopen it; fresh card Open and **Share File** must not dispatch it or grant access. Restore the original file for the multi-Share positive control. Use **Clear Completed** to remove history while preserving the files. The two previously granted URIs must no longer open, even with the old read grants still held. This tests new opens, not revocation of a descriptor or copy already obtained.

Only one fresh Android 14 / API 34 x86_64 Google APIs emulator is used per run. The runner requires GitHub-hosted KVM and the sole emulator ADB target. The test downloads use a synthetic loopback-only server over `adb reverse`; the recipient has no network permission. No APK, database, screenshot, or file payload is retained. The small JSON result is uploaded for one day and recorded in the `BROWSER_UPGRADE_RESULT` check annotation with a SHA-256. See [`test_android_download_upgrade.py`](../tests/test_android_download_upgrade.py) for host checks of the fixture, seeding, UI targeting and receipt validation. Those checks do not substitute for the Android run.

The UID, marker, and database bytes survived replacement before first v8 launch. Android then migrated the database, backfilled both name columns and created the new history indexes. No test request contained a cookie, authorization header or referrer, or reused the legacy user-agent value.

The separate app received exact bytes from the **completed-card tap**, **Open File** menu, **single Share**, and **two-file Share**. The Android sharesheet was used for both Share cases. No write or unselected-file grant was present, and write, sibling, staging, wrong-token, and descendant URI attempts failed. A still-granted URI could not open a same-size replacement; neither fresh Open nor fresh Share dispatched it. After **Clear Completed** preserved the files but removed their rows, the prior grants could not open new descriptors. This does not revoke a descriptor or copy already held by a recipient.

The [one-day JSON artifact](https://github.com/SlingshotToHeaven/browser/actions/runs/44696459590/artifacts/14611935023) is a 1,175-byte archive. The 1,981-byte result record was independently retrieved from the job's check annotation and checked against SHA-256 `a61ab624e3efe2da3f79510d3364af226915db0388ad871899f312ec791c1a22`.

The first attempt [44695143339](https://github.com/SlingshotToHeaven/browser/actions/runs/44695143339) stopped at the harness's parser for Android's randomized install path. [44695605525](https://github.com/SlingshotToHeaven/browser/actions/runs/44695605525) verified the installed migration, automatic recovery, and the first Open, then stopped when the driver couldn't select the recipient in the second resolver window. The harness was corrected for both, including Android's last-used app layout. No production code changed and neither stop was evidence of an app defect.

## Scope limits

The active and paused checkpoints were seeded, not produced by cutting off v7 mid-transfer. This is one app-private fixture and same-versionCode debug replacement. It does not cover older-than-v7 schema upgrades, a signed/release APK, shared/removable storage, other MIME handlers, or power loss. It does not verify a bad validator, a mid-copy or hard-link interruption, document/tree destination rejection, the full download credential suite, or a hardware device. No performance claim; PERF-07 remains skipped.
