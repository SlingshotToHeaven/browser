# Physical-device verification checklist

**Status: no physical-device passes recorded.** Every unchecked item is **Not run** unless it is marked **Blocked**. Use this file to track checks that need Android or real hardware. The [remediation plan](REMEDIATION_PLAN.md) records the implementation order and host results; the [README](README.md) has the detailed test commands and expected behavior. Host fixtures and API-stub compilation are not device results. An emulator can help triage Android failures, but record that run separately from a phone or tablet run.

- [ ] **SDK preflight — Blocked in the sandbox; not a hardware test.** On an SDK-equipped runner, [assemble the debug and instrumentation APKs and run lint](README.md#verify-without-a-device). `./build.sh` was retried after the Step 12 follow-up and stopped because no Android SDK was installed. API-stub compilation passed but cannot substitute for this check.
- The [SDK/device handoff](docs/device-handoff.md) and [macOS/Antigravity instructions](docs/antigravity-device-test.md) give the matched sources, package checks and run order.
- Use only the **disposable `com.browser` debug install** (label **Browser (Test)**, test APK `com.browser.test`) with synthetic pages, cookies, rules, transcripts and downloads. Leave the old installed app and its data untouched. Some checks delete data, reboot the device, change its clock, or update an existing install. Never run them on a personal browsing profile. For upgrade checks, install an approved older lab build and update it in place with the same application ID and test signing key; don't uninstall between builds. No device upgrade from the previous, different app ID is possible.
- Cover API 26 (the minimum) and a recent Android release, including the API 31+ alarm path and an API 29+ device with a terminable WebView renderer. Record the Android build, ABI, page size and WebView provider/version (`adb shell dumpsys webviewupdate`). Where a provider feature is absent, test the supported fallback and record the feature-dependent case as skipped, not passed.
- Use **ARM64 hardware** for the bundled FFmpeg checks. The release matrix also needs a supported ARM64 configuration running with **16 KiB** pages. For paired performance runs, keep the hardware, WebView, build variant, seed data and network conditions fixed.

## Checks for the current build

### Downloads, storage and media (Steps 03–06)

- [ ] **DL-01 — Android SQLite upgrade and process death.** Seed queued, manually paused, active and completed rows, old header metadata and nonempty partials. Upgrade in place. Check that history and valid checkpoints survive, legacy headers are not reused, and only eligible jobs resume after relaunch. Kill the process during a transfer, an exclusive copy, and between final publication and DB commit. An occupied destination must remain untouched and an unverified or interrupted file must not be adopted as complete. Exercise app-private and supported shared/removable storage and compare fixture bytes. See [Steps 03–04](REMEDIATION_PLAN.md#03-validate-the-http-representation-and-commit-only-verified-files).
- [ ] **DL-02 — Actual queue and service transitions.** Change Wi-Fi, charging/battery and schedule settings while jobs are waiting or running. Background the app, recreate the service, and relaunch after a force-stop. Automatic waits should clear only when eligible; a manual pause should stay paused. With two queued HTTP transfers, change the shared speed limit to/from unlimited and pause or cancel a waiting job. Do not treat app body reads as a measurement of total wire traffic or require exact background wakeups.
- [ ] **DL-03 — WebView-to-download credentials.** Use the [two-origin fixture](tests/fixtures/scoped_downloads.py) and [Step 06 instructions](REMEDIATION_PLAN.md#06-scope-download-credentials-file-access-and-throttling). Verify cookie lookup for the actual same-origin URL and origin-only referrer; a foreign hop must drop session headers. Check both the probe and actual body/range requests, pasted/external links, retry after relaunch, and a private request that must never navigate or fetch.
- [ ] **DL-04 — Actual Open/Share delivery.** Run `CompletedDownloadGrantTest`, then Open from both download surfaces and Share one and multiple files through Android's chooser to a separate app. Check that it can read only the selected committed bytes, can't write or read siblings or staging files, and can't acquire a new grant after the row is removed or its file replaced. Confirm document/tree destinations are rejected by the filesystem-only writer, not reported as successful SAF writes.
- [ ] **DL-05 — Blob transfer through the real WebView.** Use the [blob fixture and steps](REMEDIATION_PLAN.md#05-fix-stream-and-blob-completion-paths). Dismiss before confirmation: no fetch, job or staged file. Confirm and verify the exact fixture bytes and SHA-256. Repeat with queued admission, cancel, same-URL reload, tab close, another origin/frame, stall, short input and an occupied destination. No stale delivery may complete a different attempt; unsupported providers must fail clearly without a bridge fallback.
- [ ] **DL-06 — Bundled ARM64 FFmpeg and playback.** On Android, mux and play known separate A/V, ranged HLS/fMP4 and HLS/MPEG-TS fixtures; verify both required tracks. Check supported encrypted HLS as well as missing audio, bad/short input, unsupported DASH/MPD, and a mux failure. A failed case must not publish a manifest or raw track as success. Host CLI playback does not load the app's JNI libraries.

### WebView, privacy and filters (Steps 07–10)

- [ ] **WV-01 — Real callback ordering and session recovery.** Use the [tab fixture](README.md#verify-browser-chrome-and-renderer-recovery). Exercise rapid same-URL reloads, redirects, Back/Forward, SPA history, background-tab loading while editing the address bar, and process restart of committed versus pending loads. Verify chrome stays with the foreground tab, the correct recovery point and regular cookie state survive, and retired picker/media callbacks cannot affect a replacement page.
- [ ] **WV-02 — Home and renderer boundaries.** The bundled main-frame home may show its authorized local bookmarks; an ordinary page, child frame or stale document may not. Test fallback providers, legacy home recovery, and renderer loss shared across multiple tabs. Restore one affected tab, switch or close the others, and repeat with an armed picker or active blob. Also exercise renderer loss in the preview editor, comic verification and script syntax views.
- [ ] **WV-03 — NoScript and actual playback.** With [the script fixture](README.md#noscript-and-page-script-policy), check GET, cross-origin redirect, POST, child frames, SPA and restore while NoScript is on; turn it off and verify normal scripting returns. Verify document-start and fallback behavior across rule/toggle changes. On actual YouTube pages and supported embeds, check playback and player replacement; unrelated sites and disallowed frames must not receive YouTube hooks.
- [ ] **PR-01 — Private-mode refusal and truthful clearing.** Private entry from home, the tab picker and cold/warm intents must not create a regular tab. On [two fixture origins](README.md#private-tabs-and-clearing-browser-data), test cancel and cookie-only, cache-only, storage-only and history/tab cleanup separately, including process restart. Verify unrelated app data remains. Record which WebView data was actually removed; a clear request is not proof that IndexedDB, Cache Storage or workers were erased.
- [ ] **RULE-01 — App preview, commit and refresh.** From a disposable v2 catalog, make an exact replacement with a removal, then a merge. Compare the reviewed and installed rules, observe requests and cosmetics on a loaded fixture, and restart. A stale preview, invalid section or oversized input must leave the active snapshot unchanged. Confirm that a changed snapshot refreshes existing pages under the new policy. Use staging only; local Workerd passed, but neither deployment nor app/device integration is signed off.
