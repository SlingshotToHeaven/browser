# Privacy Browser: ordered remediation plan

**Baseline:** `e83d2fa08c17dce89d8ba52c22474e89126f16d7`. This plan combines the project/build review, the correctness and privacy audit, and all nine performance findings. It is an implementation order, not a claim that any fix has shipped. The feature roadmaps are separate.

**Start here:** make the build and regression checks repeatable, then contain paths that can corrupt data, cross a privacy boundary, or execute without consent. Repair those paths before performance refactors. Within performance work, scope the YouTube defuser first; then fix session persistence before changing how tabs are restored or evicted.

**Execution status:** Steps 01–21 have local implementation or containment, host evidence, and procedures for the remaining checks. Step 12 now includes an Android fixture for the real Agent sheet and a non-destructive transcript upgrade with explicit legacy cleanup. Steps 18–20 have paired-build sources and host work counts, not physical performance results. The test-source ZIP carries those sources and [macOS/ADB instructions](docs/antigravity-device-test.md); the candidate installs separately as `com.browser`. The user-requested testing-branch handoff is not acceptance or authorization to promote to `main` or release. Private tabs, image uploads, and direct SAF publication remain unavailable. SDK build/lint, Android runtime and upgrade checks, the physical push gate, signed release verification, and owner-controlled provenance and credentials are still open. No Worker deployment or release sign-off.

**Latest host verification (after the `com.browser` handoff):** 329 JVM tests with host FFmpeg 8.x, 36 Python tests, 25 Node tests, and 6 local Workerd tests passed. Candidate main, host test, and instrumentation Java compiled against API-34 and AndroidX signatures, as did production Java for the matched performance baselines. The host runner used a no-op Android tracing shim. All 23 source checksums and eight checkout ARM64 ELF alignment checks passed. `./build.sh` stopped before Gradle because the Android SDK was missing. No APK, Android lint, instrumentation execution, or device measurements were produced.

## How to work through the plan

- **Use the numbered merge order.** A step can be split into several small PRs. Independent investigation can run in parallel, but don't re-enable a contained feature until its acceptance checks pass. Keep optimizations separate from changes to blocking, privacy, or data-loss behavior so comparisons and rollbacks are meaningful.
- **Add a regression check with each change.** Use fake providers, disposable profiles, and controlled fixture servers. Never copy live browsing data, cookies, user rules, signing keys, or test credentials into fixtures, traces, or logs. Track host, Android runtime and physical-device results separately. Use the [physical-device checklist](DEVICE_TEST_CHECKLIST.md) for outstanding checks and evidence.
- **Keep migrations recoverable.** Test upgrades from the baseline with nonempty data, failure during write, re-launch after interruption, and retry. For risky features, a safe disabled state is a better rollback than restoring known-unsafe behavior.

### Milestones

| Steps | Milestone | Gate |
| --- | --- | --- |
| 01–02 | Reproduce and contain | Repeatable test build on a configured runner; affected paths fail clearly and safely until repaired. |
| 03–06 | Trust downloaded files | Completion means verified contents, a committed destination, and the current attempt's state. |
| 07–10 | Trust browsing and imported rules | Untrusted pages and imports cannot acquire native privileges; private storage and deletion claims match behavior. |
| 11–13 | Trust actions and feature results | Side effects require the right approval or consent; failures and incomplete outputs are not reported as success. |
| 14–20 | Make interaction cost bounded | Check work counts and compare device traces without weakening protection. |
| 21 | Release | Verify upgrades, packaging, native libraries, size, and distribution requirements on the actual release artifact. |

## A. Reproduce and contain

### 01. Establish the build, fixtures, and baseline

- Document the baseline toolchain (JDK 17, AGP 8.6.1, compile/target SDK 34, min SDK 26) and portable `ANDROID_HOME`/SDK setup for [`build.sh`](build.sh). Pin a compatible Gradle wrapper and CI toolchain. Build all modules; run the existing JVM suites, Android lint/resource checks, and smoke checks for the Worker and optional bridge. Separate test artifacts from release signing.
- Turn the strongest offline evidence into permanent tests: direct transfer integrity and attempt ownership, stream/blob completion, rate-limit changes, exact filter-state application, concurrent Worker publishes, and multi-tool turn correlation. Use fixture data only. Add narrow WebView instrumentation for origin, renderer-loss, privacy, and tab lifecycle checks; fake JVM objects are not evidence of WebView behavior.
- Record a profileable release-like baseline on a physical Android device. Add trace spans and counters for first visible page, session captures and writes, live WebViews, script scans, probes, and DB queries. Use the [measurement matrix](#measurement-matrix). Don't delay obvious containment while collecting detailed traces.
- **Exit:** another contributor can build and run the isolated checks from documented commands. Missing device results are marked *not run* rather than inferred. The previous audit did not build an APK or collect Android timings.

### 02. Contain release-blocking risks while fixes are pending

- Where integrity isn't established, don't append to legacy partial files or present output as complete. Keep partial data recoverable and make “start a fresh download” explicit. Reject unsupported stream formats and mux failures instead of returning mislabeled or incomplete output.
- Disable unauthenticated shell capability, unattended externally triggered recipe execution, automatic execution of imported scripts, and image uploads to any provider other than the one the user selected. Remove sensitive homepage bridge operations from normal browsing views until there is a trusted boundary.
- Do not advertise shared-profile browsing as isolated private browsing. On unsupported providers, clearly limit or disable that mode until step 08; suspend speculative third-party favicon fetches in private contexts. Leave normal browsing and known-safe explicit actions available.
- **Exit:** a disabled path has a visible, accurate reason and cannot report success. Record which later step and tests qualify each path for re-enablement.
- **Implemented download containment:** unsafe direct resumes require a fresh request (see step 03). DASH/MPD stream jobs fail with an unsupported-format message rather than saving a manifest as media. HLS and separate-track jobs no longer publish raw inputs when required audio or muxing fails (see step 05).
- **Implemented containment:** v1 cloud diffs are retired and v2 accepts only validated, non-executable rule data (Step 10). Shell/Termux and legacy Antigravity OAuth are unavailable, external and old alarm recipe payloads cannot execute, and new alarms only mark reminders for review (Step 11). Native image uploads and Agent captures are unavailable; image lookup sends one reviewed HTTP(S) URL, not local bytes (Step 13). Previously installed local scripts, saved transcripts, credentials, and alarms are not declared safe or erased by these changes. Private mode remains disabled (Step 08).

## B. Make downloads trustworthy

### 03. Validate the HTTP representation and commit only verified files

- In [`SegmentWorker`](downloader/src/main/java/com/privacy/downloader/engine/SegmentWorker.java), require a matching `206`, `Content-Range`, total where known, and representation validator before appending. Use a strong validator with `If-Range`; if continuity can't be proven, restart into a new partial or fail recoverably. Treat an unexpected `200` as a full response, not a range. Verify bytes received against the assigned range and reject gaps, overlaps, and short writes. A preallocated file of the expected length is not proof of coverage.
- In [`DownloadTask`](downloader/src/main/java/com/privacy/downloader/engine/DownloadTask.java) and [`DownloadDbHelper`](downloader/src/main/java/com/privacy/downloader/db/DownloadDbHelper.java), tie segment checkpoints, partial files, and representation identity to the same attempt. Reconcile recovery from a missing or truncated file and never reuse its completed rows. Reserve destinations without collisions; stage output, check publication success, and expose a completed file only after it is committed. For provider or cross-volume copies, verify the copy before marking complete. Check a supplied digest when available, not as a substitute for range/coverage checks.
- **Exit:** local HTTP tests cover full and partial responses, changed validators, invalid ranges, short bodies, missing files with old checkpoints, destination collisions, and interrupted publication. Successful output matches known fixture bytes; failure preserves a recoverable state or explicitly requires a fresh start.
- **Implemented slice:** direct HTTP uses strong ETags and `If-Range`, checks the exact `206` interval, total and body length before completion, and only reuses valid checkpoints from the verified staging file. A changed link clears representation metadata. The SQLite v4 migration does not mark old partials as verified. Start over is explicit, clears checkpoint rows, and makes a full request into a new partial without deleting the previous file.
- **Implemented filesystem publication:** the SQLite v5 reservation assigns each new job a distinct final name before it runs, including across batch and stream jobs. It does not create a placeholder or replace an existing row. Legacy rows keep their paths on upgrade and claim a usable name when they next run. The shared publisher syncs staged bytes, checks an optional user-supplied SHA-256, and uses an atomic no-replace hard link where supported. On volumes without links or across directories/volumes, it creates the destination exclusively, then reads the copy back to verify length and SHA-256. The app reports `COMPLETED` only if the database still owns that reservation and staging path. A stopped/rejected publication rolls back the output when ownership can be verified; a direct download keeps its checkpoint on a publication error.
- **Host evidence:** 71 downloader JVM tests cover queued and existing names, concurrent final-name contention, copy corruption and interruption, rejected completion, supplied-hash mismatch, and the HTTP, stream, data URL, and blob publication paths. An ext4→tmpfs smoke test also verified exact copied bytes. Host SQLite checks of the Java SQL preserved history and checkpoints across v3→v5 and v4→v5, including duplicate legacy names, and rejected duplicate claims and stale completion updates. This is not an Android database migration test.
- **Remaining gate:** externally visible filesystem copies can appear at the destination while being verified; the app does not list them as complete. Step 04 implements conservative recovery from an interrupted commit; actual process death during copy or between filesystem publication and the SQLite commit still needs on-device testing. Verify Android external/removable storage and OS support for the copy/link paths. Direct SAF/content-provider writes are not implemented in the current downloader and are not covered by these tests. The in-place database upgrade and the SDK checks are separate gates. [Report 7](docs/android-test-followup.md#report-7-changed-http-file-and-late-destination-collision) observed correct stale-resume rejection, exact bytes after explicit Start over, and refusal to overwrite a late entry. This did not interrupt the actual copy/commit or verify other volumes.

### 04. Make the download queue safe to restart or reconfigure

- Give [`DownloadEngine`](downloader/src/main/java/com/privacy/downloader/engine/DownloadEngine.java) one owner per job and generation. Accept callbacks only for the current attempt. Make pause, cancel, restart, retry, completion, and recovery idempotent; transactionally update the corresponding job/checkpoints where needed. Old callbacks must not evict or complete replacements.
- Define the transition table for pending, running, paused, waiting for Wi-Fi/schedule/battery constraints, failed, and completed. Distinguish manual pause from unmet constraints and reconcile on connection, settings, schedule-boundary, and process-start events. Keep DB reconciliation off the UI thread. Don't promise exact timing where Android cannot deliver it.
- **Exit:** deterministic interleaving tests cover restart versus late completion, concurrent pause/cancel, closing and reopening the app, a changed schedule, Wi-Fi recovery, and stable destination ownership. A waiting job is never silently converted to a manual pause.

**Implemented transition table**

| State | Automatic transition | Explicit action |
| --- | --- | --- |
| `PENDING` | Recheck all constraints before capacity. If eligible and a slot is free, claim a fresh token and go to `CONNECTING`. | Pause or cancel. |
| `CONNECTING` / `RUNNING` | Run only under that token. An unmet constraint records the appropriate wait and stops the worker. Successful publication requires the token, reserved name, staging path and `RUNNING` state; transfer failures become `FAILED`. On a new process, interrupted transfers return to `PENDING` without adopting an existing output. | Pause or cancel; retain ownership until the worker and its cleanup exit. A committed completion is not reversible by pause or cancel. |
| `WAITING_FOR_SCHEDULE` / `WAITING_FOR_BATTERY` / `WAITING_FOR_WIFI` | Re-evaluate together in that order, even at capacity. Clearing or disabling a constraint exposes the next unmet constraint, or returns the row to `PENDING`. Battery saver waits when unplugged at 15% or below. | Pause to opt out of automatic resume, or cancel. Retry cannot bypass constraints. |
| `PAUSED` | No auto-resume, including after relaunch. | Resume using the saved checkpoint if verified; direct HTTP can also start over once the worker drains. |
| `FAILED` | Preserve history and the destination reservation. | Retry or, for direct HTTP, start over without reusing the old partial. |
| `COMPLETED` / `CANCELLED` | Preserve terminal history. A cancelled row is not runnable. | Remove from the queue; completed history may also be cleared without deleting files. |

- **Ownership and recovery:** SQLite v6 adds an attempt token checked by worker status, progress, staging, checkpoint and publication writes. The same [controller](downloader/src/main/java/com/privacy/downloader/engine/DownloadQueue.java) holds all task types through exit, even after a stop or committed result. Progress is checked at posting and delivery; completion and failure notifications derive from the persisted outcome after exit and are suppressed if a retry or removal wins before delivery. Restart/link edits do not reset a still-owned staging path. A deletion waits for drain before releasing the reservation; if the app is killed first, the non-runnable row remains and removal can be requested again.
- **Conservative publication recovery:** if the reserved name is occupied when the job becomes eligible, fail the job without overwriting, renaming, or removing that entry. It could be an interrupted hard link/copy or another file, even if its bytes or size look right. Keep the name and checkpoint. A user can move the occupying file before retrying, or enqueue under a different name. An interrupted direct HTTP job still needs a verified checkpoint to resume. A blob source is tied to the first admitted attempt (see step 05); confirm a new download from the original page when that source is gone.
- **Host gate:** the [deterministic JVM suite](downloader/src/test/java/com/privacy/downloader/engine/DownloadQueueTest.java) controls worker exit and delayed callbacks, including a running worker during pause/cancel, a late publication/retry, in-process constraint changes, and a new controller over the same saved rows. The [host SQLite suite](tests/test_download_queue_sql.py) exercises v3/v4/v5→v6 SQL with nonempty rows, database close/reopen, token and state predicates and transactional checkpoints. Interrupted hard-link and short-copy fixtures preserve both paths. The full downloader JVM suite passed 85 tests, plus 4 host SQLite checks. These are not Android lifecycle or storage tests.
- **Device gate:** [report 6](docs/android-test-followup.md#report-6-saved-download-checkpoints-after-relaunch) observed automatic resume of the interrupted HTTP job after explicit relaunch, no requests for the paused job until a Resume tap, and both checkpoints resuming with matching validators and exact final hashes. Still verify a real SQLite upgrade with queued, paused and completed rows, interruption during both publication paths, and occupied-name recovery. Also exercise Android service recreation, Wi-Fi loss/recovery, charging and changed schedule settings. Reconciliation runs off-main on launch/resume, connectivity, battery, settings, schedule and worker exit. The foreground service is best effort; no exact alarm, background wake deadline or recovery after a force-stop without user relaunch is promised.

### 05. Fix stream and blob completion paths

- In [`StreamDownloadTask`](downloader/src/main/java/com/privacy/downloader/engine/StreamDownloadTask.java), distinguish manifests, segments, and final containers. Reject unsupported DASH/MPD explicitly until a real path is tested. Validate HLS range responses and stream bounded buffers to staging files. Fail closed on required audio or mux errors; never publish a manifest or a raw video-only fallback as the requested combined file. Reuse step 03's verified publication contract.
- For [`BlobDownloadManager`](downloader/src/main/java/com/privacy/downloader/interceptor/BlobDownloadManager.java) and [`BlobDownloadTask`](downloader/src/main/java/com/privacy/downloader/engine/BlobDownloadTask.java), start transfer only after confirmation. Bind one intake to its originating tab/document and attempt. Enforce bounded input, declared length when available, and an explicit successful end. Clean up on dismiss, cancel, timeout, tab close, or failed publication.
- **Exit:** valid fixtures produce playable files with the expected tracks; unsupported, short, timed-out, dismissed, and failed-mux cases produce no successful file or stranded task. Include a native mux smoke test in step 21.
- **Implemented blob intake:** the prompt holds metadata only. Confirming registers a one-shot source under the new job ID; only its first claimed queue attempt starts the read. A per-WebView listener pins the committed main document's reply endpoint and checks the view, frame, origin and transfer token. The downloader does not buffer to cache or reattach by URL. The script streams after a native start message, waiting for a worker acknowledgement before the next frame. The worker stages at most 64 KiB per frame and 512 MiB per transfer and requires matching offsets, any declared byte count, and explicit success. Navigation/tab/activity teardown revokes unfinished intake. Cancel, timeout or failure releases the channel, and the worker removes unpublished staging. After intake seals, publication still requires the current queue attempt and the shared no-replace checks. An unstarted source expires after two minutes; active reads time out after 30 seconds idle or ten minutes total. Blob jobs cannot be resumed from persisted state or redirected to a different URL.
- **Implemented HLS staging:** each attempt streams validated responses into staging with a 64 KiB read buffer, a bounded cleartext buffer for AES-128, and a 4 KiB media prefix check. Range requests require the exact `206` interval and consistent framing. Short, overlong, non-media, invalidly encrypted, and ambiguous responses fail closed. A retry truncates back to the current segment's starting offset. Required-track maps, FFmpeg exit/empty-stream checks, MP4 box validation and the step 03/04 publication fences remain in place. DASH still fails explicitly.
- **Host evidence:** 105 downloader JVM tests passed, including 23 [stream containment tests](downloader/src/test/java/com/privacy/downloader/engine/StreamDownloadContainmentTest.java), [blob publication tests](downloader/src/test/java/com/privacy/downloader/engine/BlobPublicationTest.java), and 3 [real CLI playback tests](downloader/src/test/java/com/privacy/downloader/engine/StreamDownloadPlaybackTest.java) with host x86-64 FFmpeg `n9.0.2-17`. The CLI decoded both tracks of separate A/V, ranged HLS/fMP4 and HLS/MPEG-TS outputs; missing separate or in-band audio failed without publication. The newer host binary also passed the MPEG-TS case that previously crashed the older CLI. Four [Node tests](tests/blob_intake.test.mjs) ran the actual page script with a simulated sender/reader. These results do not exercise WebView callback delivery, Android storage, or bundled JNI.
- **Device blob gate:** start with the [download boundary runbook](docs/android-test-followup.md#b-real-webview-blob-intake-dl-05-subset). Report 5 passed dismiss-before-fetch, a verified complete blob, one byte short, and a same-address reload after the first stalled chunk. Also exercise cancel, tab close, another origin/frame, idle timeout, waiting queue and an occupied destination; a later attempt must not complete the old job. The [manual report](docs/android-test-followup.md#latest-manual-report-settled-restart-and-debug-playback) covers TS/fMP4 playback and missing audio on 4 KiB debug ARM64, not all native cases or the signed build. Verify the full tracks/containment matrix on supported devices before release (step 21).

### 06. Scope download credentials, file access, and throttling

- Centralize request-context policy for direct/ranged downloads, redirects, link grabber, media probes, streams, comics, and other fetchers using browse state. Resolve cookies and permitted referrer data for the actual destination on each hop; never blindly forward the initiating page's headers. Keep private context private and out of persistent job metadata.
- Give [`DownloadsActivity`](downloader/src/main/java/com/privacy/downloader/ui/DownloadsActivity.java) narrowly grantable `content://` URIs for open/share; verify the Android/provider/SAF flows. Avoid unrestricted file paths and respect the reserved destination policy from step 03.
- Replace the [`SpeedLimiter`](downloader/src/main/java/com/privacy/downloader/engine/SpeedLimiter.java) wait math with cancelable permits based on a monotonic clock. Split requests larger than the bucket capacity, handle unlimited mode explicitly, and wake waiters when settings change. Document which network paths honor the limit, and apply it consistently before advertising it as global.
- **Exit:** tests cover cross-origin redirects, file open/share with grants, a chunk larger than the bucket, live changes to/from unlimited, cancellation, and concurrent jobs without stalls.

- **Implemented:** [`RequestContext`](downloader/src/main/java/com/privacy/downloader/net/RequestContext.java) and [`ScopedHttp`](downloader/src/main/java/com/privacy/downloader/net/ScopedHttp.java) scope native GET/HEAD redirects to the verified regular page's scheme, host, and effective port. Cookie lookup uses the actual URL, `Referer` is origin-only, and a foreign hop drops session authority for downstream requests. A conditional direct range still cannot redirect; a probe's narrowed scope carries into its verified range requests. HLS children and comic image extraction use the scope of the response that named them. Unbound requests and background media probes are anonymous; service-worker detection no longer borrows the active tab. Private-tab download and media entry points are disabled pending profile isolation. The queue attaches the context to one job and its first attempt in memory. Schema v7 clears legacy `cookies`, `referrer` and `user_agent` values without changing reservation/validator/checkpoint data. It doesn't infer ownership of old files, wipe WebView storage, or promise secure erasure of old blocks/backups.
- **Implemented:** [`CompletedDownloadProvider`](downloader/src/main/java/com/privacy/downloader/provider/CompletedDownloadProvider.java) is non-exported and has no file-path/root mapping. It checks the exact committed job and attempt, and verifies a regular file's publication identity on open without following a leaf symlink. Missing, changed, and pre-v7 files without an identity fail closed. The single and bulk share intents and both open surfaces grant read access on exact `content://` URIs using `ClipData`; no prefix, write, or persistable grants. Existing destination reservations and no-replace publication still apply. This is not SAF publication.
- **Implemented:** One monotonic, bounded token bucket paces queued HTTP body reads (direct/ranged, HLS manifests/keys/segments, and separate A/V). Oversized reads consume smaller permits, concurrent readers take turns, and stop and rate changes wake waiters. Browser traffic, metadata and standalone probes, comics, blobs/data URLs, and local IO are outside the cap. The setting is labeled **Queued HTTP speed limit**, not an app-wide or wire-rate limit.
- **Host evidence:** 123 downloader JVM tests passed with host FFmpeg enabled, including [two-origin redirect fixtures](downloader/src/test/java/com/privacy/downloader/engine/ScopedHttpTest.java), verified range and HLS child scope, queue ownership/restart, [deterministic limiter tests](downloader/src/test/java/com/privacy/downloader/engine/SpeedLimiterTest.java), and [concurrent direct/HLS transfers](downloader/src/test/java/com/privacy/downloader/engine/SpeedLimitedDownloadTest.java). Five [host SQLite checks](tests/test_download_queue_sql.py) cover v3–v6 upgrades, legacy header removal, preserved checkpoints, and completed-only grant eligibility. API-stub compilation does not run Android SQLite, WebView or URI grants.
- **Device gate (not run):** Run [`CompletedDownloadGrantTest`](app/src/androidTest/java/com/privacy/browser/downloads/CompletedDownloadGrantTest.java) using the [README command](README.md#open-or-share-a-completed-download). On API 26 and a current Android version, test Open from Downloads and the dialog, and single/multi Share through the system chooser to an independent recipient. Use app-private and writable shared/custom destinations; confirm the recipient can read exactly the selected bytes, not write or read a sibling/staging file. Repeat after deleting the row and after replacing the file at its old path. Try a document/tree URI as a destination: filesystem-only writes must reject it, not silently fall back to that provider. SAF publication needs its own implementation and device tests.
- **Device credential fixture:** follow the [native download header run](docs/android-test-followup.md#a-native-download-header-scope-dl-03-subset). Long-press and use **Download Link with Manager** so WebView navigation does not contaminate the results. Report 5 passed both probe and body through same-origin, foreign and round-trip links, and an unbound Add Download. Report 6 observed that both resumed requests after relaunch were anonymous after initially scoped requests; still check external-link intake and that private admission never navigates or fetches. Set the limit to 2 KiB/s with two queued HTTP jobs, pause one and change the setting to unlimited and back; check cancellation and aggregate rates separately from network-stack buffering.

## C. Repair the browser's trust and privacy boundaries

### 07. Give native navigation sole ownership of chrome and lifecycle

- In [`MainActivity`](app/src/main/java/com/privacy/browser/MainActivity.java) and [`PrivacyWebViewClient`](app/src/main/java/com/privacy/browser/PrivacyWebViewClient.java), route address/security indicators, progress, and active-tab UI through trusted native navigation events. Key callbacks to tab and document generation; background or stale events can update their own model, not foreground chrome. Don't persist or display a URL just because page JavaScript reported it.
- Serve the bundled homepage at a dedicated internal origin, with a narrow origin- and main-frame-bound bridge. Treat unsupported providers conservatively rather than re-exposing bookmark APIs globally. Review the other bridges so each accepts only its intended data and cannot authorize native actions by itself.
- Handle `onRenderProcessGone` for every affected view: detach and destroy it, drop stale callbacks, and show a recoverable restore state. Unregister Activity-owned callbacks from process-wide media, AI, and service-worker hooks on teardown.
- **Exit:** an ordinary site or subframe cannot read homepage bookmark metadata or change browser chrome; switching while a background page loads keeps foreground UI correct; a renderer exit leaves an operable shell and a recoverable tab.

- **Implemented:** Only native main-frame commit/visited-history callbacks publish the tab URL. Pending loads keep the last committed recovery point; title, progress, security, and page work are scoped to the current `WebView` and document, and UI effects require foreground ownership. Legacy URL/title metadata is retained, but old opaque WebView back-stack bundles are not restored. The framework does not provide document IDs on all API 26 callbacks; coincident same-URL native events and provider callback ordering remain a device gate.
- **Implemented:** The bundled home uses `https://home.privacy-browser.invalid/`, with a main-frame GET asset handler, restrictive CSP, exact-origin listener, per-response delivery proof and per-commit token. Unsupported providers retain search and links, not native home actions or bookmark access. Video/comic messages are bounded candidates, not native fetch or launch commands. Native menu actions arm one-shot image/element pickers; legacy anti-adblock and fingerprint telemetry that pages could fabricate was removed. Document-start script policy is handled separately in Step 09.
- **Implemented:** Each terminated view detaches before destruction, invalidates its blob and page scopes, and leaves a restore action for the last committed URL. The preview, CAPTCHA and syntax-check WebViews also handle renderer loss. Activity teardown removes only its own media and AI references; there was no Activity-owned service-worker hook in the source to unregister.
- **Host evidence:** 9 targeted JVM navigation/message tests passed. App, libraries and authored instrumentation sources passed a Java 17 API-34/AndroidX-stub compile. The existing 12 Python and 8 Node checks passed. See [the device gate](README.md#verify-browser-chrome-and-renderer-recovery) for callback coverage that the host does not exercise.
- **Build/device:** Not verified. The sandbox still has no Android SDK or device. [`BrowserViewLifecycleTest`](app/src/androidTest/java/com/privacy/browser/BrowserViewLifecycleTest.java) is authored, not run. Test same-document history, shared renderer loss, cookie handoff, same-URL reloads and fallback behavior on actual providers before calling this a release pass.

### 08. Isolate private data and make deletion truthful

- Use a separate private WebView profile where the provider supports verified isolation and deletion. Else use a supported isolated process/storage design or keep private mode unavailable; skipping history alone is not isolation. Test cookie, Web Storage, cache, service-worker, preview, and favicon behavior across regular/private profiles and process restarts. No private history, session snapshots, previews, or probe metadata should be written to the regular profile. Upgrades cannot retroactively separate previously shared data; disclose that and offer an explicit cleanup choice, not an automatic wipe.
- In [`FaviconManager`](app/src/main/java/com/privacy/browser/favicon/FaviconManager.java), remove speculative Google fallback by default; prefer page icons or local placeholders. Do not write private icons into regular caches. Any optional remote lookup must have clear scope and consent.
- Define exactly what “clear this site” and “clear all” remove, including app-owned data versus WebView storage. Use supported per-origin APIs only when their scope matches the promise; show limitations rather than silently clearing other sites or claiming full deletion. Apply one policy to browser UI and [`ToolDispatcher`](app/src/main/java/com/privacy/browser/ai/ToolDispatcher.java).
- **Exit:** two-site/two-profile device tests verify both isolation and wipe scope, including restart and last-private-tab close. Global clear removes what the UI explicitly promises and does not affect unrelated files.

- **Implemented (fail closed):** The app does not allocate a default-profile WebView for a private request. The homepage, tab picker and warm/cold intent paths report unavailability; a private URL is never silently opened in a regular tab. Older builds shared data and the upgrade does not wipe or migrate it. A named AndroidX profile alone is not an ephemeral session, and the provider's deletion contract is not a synchronous disk wipe.
- **Implemented:** Favicon lookups read only icons previously received by a regular WebView or show a local monogram. There is no Google lookup. Per-site deletion is explicitly unavailable with the pinned WebKit/API policy; no `deleteOrigin` or best-effort cookie expiry is presented as a site wipe. Native UI and the tool use the same immutable all-sites plan and a fresh native confirmation. Cookies report the provider callback, cache and legacy Web Storage report requests, and optional app history/tab cleanup preserves unrelated data. The tool must specify `domain: "*"` and explicit categories and cannot clear app history through that tool.
- **Host evidence:** 5 Step 08 JVM tests passed (scope rejection, selected categories, private gate, local icon key checks); 14 together with Step 07. The 123 downloader JVM regressions passed with host FFmpeg enabled. API-34/AndroidX-stub compilation passed; the pinned WebKit 1.12 API lists `MULTI_PROFILE` but not `DELETE_BROWSING_DATA`. No dependency or SDK change was made to claim broader deletion.

## Measurement matrix

Use the same device, build configuration, WebView version, data seed, and network conditions for paired runs. Record spread (e.g. median and p95 where the sample supports it), not just the fastest run. Use Macrobenchmark for launch/interactions, Perfetto for UI and renderer traces, and counters for deterministic pass/fail checks. Set latency, frame, and memory targets after collecting the baseline and before shipping performance patches. Require the structural checks below as well as device results; don't treat a noisy timing difference as an improvement or trade it for weaker protection.

| Scenario | Measure | Expected structural change |
| --- | --- | --- |
| Cold fresh install; cold restore with 1/10/30 tabs; warm resume | First frame **and** time to the selected page becoming visible; UI I/O; WebView count | Active-first restore, no optional work blocking first navigation, unchanged settings don't reapply across all tabs. |
| Switch tabs and open the overview; cycle through 30 tabs | Tap-to-visible frame, frame overruns, app plus renderer memory, snapshot and preview counts | No all-tab save on switch; bounded live views and thumbnail bytes. |
| Static site, mutation-heavy feed, YouTube and embeds | Scroll frame overruns, document-wide scans, script timers, request overhead, blocked/allowed decisions | Zero off-site YouTube hooks; less script and request work without weakening filters. |
| Omnibox with 1,000 and 50,000 history rows; normal and private | Key-to-visible suggestions, main-thread DB work, stale-result suppression | Zero synchronous search DB calls in the text watcher. |
| Media-heavy site, navigation away, idle hidden tab | Extra requests/bytes, concurrent probes, stale results, process CPU | No speculative duplicates; probes bounded and cancelable. |
| One active download with small vs. large saved history; no active tasks | Per-refresh SQL/cursor work, UI frames, idle work | History-independent notification refresh; no active-download ticker when idle. |
